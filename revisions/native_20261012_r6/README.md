# r6：Smol iLLaVA 作者 FP16 舍入兼容

Smol 的合并行现在先 `.half()`，再 `.to(x.dtype)`。前一步保留作者 FP16 舍入；后一步满足 `scatter_` 源/目标类型相同的要求，FP32 下不会取消已经发生的舍入。仅改合并行的类型转换与说明，选点、排序、权重、合并和恢复规则不变；没有把整个模型转成 FP16。

相对 r5，仅修改 `smol/smol_merge_ports.py` 与其源清单，并增加一个舍入/写回回归测试。其他模型与方法文件保持 r5 字节，Qwen 作者 `.half()` 和 QK32 保护保留。

新版在 V100 实测 FP16/FP32，各完成同一道原始五图 MMMU_val/3414 请求的 14 个模式：四方法与禁用/恢复 Dense，共 **28 次完整自然 EOS 生成**。四个 CUDA 舍入/写回组件测试、完整 Smol CPU 测试、源身份、同请求双计时事件、方法激活、Dense 恢复、journal/导出一致性由独立审计核验通过。候选输出没有要求与旧迁移逐元素一致。

这是有界回归，不是全数据集准确率或速度结论。原有退出清理的禁止删除提示保留，未改服务器保护。附加图片验证按用户要求跳过。

## 重建和部署

`materialize.py` 使用本目录 `FILE_MAP.json`、96 个公开模板与 6 个哈希固定本地作者依赖精确重建已测试的 102 文件。local-author-overlay 须用新版 r6 私有发布，其中 Smol 的依赖已更新；旧 r5 依赖不能冒充新版。

服务器已部署在 SMOL_HALF_RESTORE_R6_20261012 交付目录的 native_release_20261012_r6。统一入口 `run.py` 及参数不变，仍是有界回归入口。旧 r5/r4 目录、提交和证据保留。
